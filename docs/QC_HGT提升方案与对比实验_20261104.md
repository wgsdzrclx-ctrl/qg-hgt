本报告基于 2026-11-04 对会议论文 PDF、当前 `paper_code` 源码、配置、训练日志、checkpoint 和原始预测的审查。结论是：QC-HGT 有明确值得优先修复的表示与训练瓶颈；目前不能承诺某个改动必然大幅提高准确率，也没有证据支持已经超过最新方法。本次未修改原模型、配置、论文或历史结果，未启动新训练。

**先看真实起点。** 论文主要指标是 Macro-F1，不是 Accuracy。以下使用五种子均值；单位均为百分数，两个指标分别计算。

| P1 / Clean | GCN | 16.22 | 14.59 |
| P1 / Clean | HGT | 41.56 | 43.46 |
| P1 / Clean | QC-HGT | 43.49 | 44.93 |
| P2 / Unseen Combination | HGT | 40.48 | 41.30 |
| P2 / Unseen Combination | Consistency Only | 42.62 | 43.78 |
| P2 / Unseen Combination | QC-HGT | 42.18 | 42.39 |

**优先级 1：保留故障幅值与变量身份。这是已能直接验证的信息瓶颈。**

| 问题 | 代码证据 | 本次数值验证 | 建议 |
| --- | --- | --- | --- |
| 每个节点的七维统计量单独做 LayerNorm | `models/qc_hgt.py:483–494,564–568` | 恒为 10 与恒为 100 的窗口，归一化后最大差只有 1.19e-7 | 训练集拟合逐变量固定尺度，保留幅值支路，取消原始七维向量的样本内 LayerNorm |
| 没有使用物理变量身份 | 图文件写入索引；`models/qc_hgt.py:492–494,607–611` 共享投影、均值池化 | 交换同单元 XMEAS1、XMEAS2 完整窗口，模型 logits 最大差为 0 | 加 52 个变量 ID embedding、6 个单元 embedding，贯穿编码、一致性评分与读出 |

第一个探针是恒定窗口反例，不代表所有真实故障都被完全消除；它证明当前表示在某些重要幅值变化上不可辨识。第二个探针使用随机初始化模型的 eval 前向，结合当前对称拓扑与共享参数说明结构性限制，不是训练精度测量。

推荐预处理为 `x_std[t,j]=(x[t,j]-mu_train[j])/max(sigma_train[j],eps)`。只在训练 run 拟合；对正常训练段拟合和全部训练段拟合作为两种验证集候选。可以对标准化后的七种统计量再做训练集固定的“变量×统计量”尺度校准。保留投影后隐藏表示的 LayerNorm，不要混同为必须删除所有归一化。原 CNN 的 `masked_window_standardize` 也会移除单窗均值/尺度，新增强时序基线需要保留均值/幅值旁路。

第一轮保持旧退化定义：仍在原始物理单位注入相同噪声/漂移，再固定标准化。若改为按每个变量标准差注入相对噪声，应定义新鲁棒性协议并对全部基线重跑，不能沿用旧表。当前绝对噪声幅值跨不同量纲不可比，也是后续协议改进的理由。

索引已经在 `data/tep_hetero_graph.py:246–252` 保存，但 `models/common.py:168–227` 适配路径还需要同步传递，不能只在图对象里加 embedding 输入却在统一接口丢掉它。变量 ID 不是故障标签，也不需要语言模型；先用小 embedding 验证收益，再决定是否加入文本元数据。

**优先级 2：让原始时序进入诊断主干。**

当前 QC-HGT 的分类主干只读取七个统计量，原始窗口只用于质量描述量。统计量不能完整保留局部振荡、相位、变化顺序和变量之间的滞后关系。推荐新增一个共享的轻量时序编码器，而不是首先堆深图网络：

```text
原始窗口与观测掩码
  → 训练集固定逐变量标准化
  → 每变量共享多尺度 TCN，输入 [x_std, mask, Δx]
  → 拼接七维统计特征、变量 ID 与单元 ID
  → 2 层关系感知图传播
  → 带身份的节点读出 + 保留变量顺序的轻量残差支路
  → 21 类分类
```

差分需要同时使用相邻观测掩码，不能把补零产生的跳变当作真实差分。隐藏维度先用 64，时间卷积核候选 3/5/9、膨胀率 1/2/4；这些是待验证起点，不是已确定最优参数。先保持 W=30 以隔离编码器收益；之后分别验证 W=60/100，不同时修改全部因素。严格在线设置只使用当前及过去样本。

可以保留现有自定义骨干，先测输入表示改动；再比较真正的多头 HGT/GATv2 或局部消息传递加全局注意力。当前原生 HGT 是 PyG 多头 `HGTConv`，QC 层实际是单头加性关系注意力（`models/qc_hgt.py:415–442`），两者不是同一骨干。新结果必须包含“同一个时序前端+同一个图骨干、同时关闭 q/c”的控制组，不能把时序编码提升归功于质量/一致性。

**优先级 3：让质量与一致性真正改变消息量，而不只是邻居排名。**

现有公式对每种关系、每个目标的入边做 softmax。如果只有一个入邻居，权重恒为 1；给 logit 加任何质量/一致性项都不会改变该条消息。当前 `monitored_by` 有 41/41 个目标如此，`controlled_by` 为 11/11，`flows_to` 为 4/5。多个邻居同时受到相同质量惩罚时，共同偏置也会抵消。

因此建议对消息 value 再加一个有下限的门控，例如 `message_ij = alpha_ij * gate_ij * V_r(h_j)`，初始试验可用 `gate_ij = g_min + (1-g_min)*r_j*c_ij`，保留 self residual 并验证 g_min。logit-only、value-only、二者联合应分开消融。该乘积只是候选，不能把低兼容性直接当作错误观测：真实过程故障也可能改变关系，过强门控会删掉诊断信息。

其他应同步处理的质量问题：

- 执行器也在 52 变量退化范围内，但可靠性固定为 1；应覆盖 sensor 与 actuator。process_unit 初值在门控前直接平均不同物理单位统计量，应改为编码后、质量感知聚合，避免污染绕过传感器门控。
- P1 干净训练的质量目标基本全为 1，没有学习一般退化质量的充分监督。若使用合成退化预训练或 clean/corrupt 配对训练，必须单列增强训练协议，不能继续称严格 clean-only P1。
- P2 每窗仅选少量变量退化，质量 MSE 被大量未退化节点主导，且单一最大强度退化对应 q* 仍为 0.75。可在训练损失中平衡受影响/未受影响节点，加入同节点不同强度的排序约束、逐变量尺度校准。受影响标记只能用于训练监督或事后分析，不能成为推理输入。
- 全 Sensor 平均可靠性约 0.997，只能说明整体均值很高，不能单凭该均值证明受损传感器全部预测失败。应分别报告受损/未受损节点的误差、排序相关性、分位数和质量分布。
- 第六个 timestamp-delay 描述量实际回退为零。没有真实可观测时间戳时，应去掉或明确不可用，不能注入人工 shift 强度作为测试输入。
- 本次读取十个 QC checkpoint，融合系数均为正；没有证据称已出现负门控。softplus 非负约束可作为后续设计，不能冒充已验证修复。

**优先级 4：改进一致性监督，并避免辅助任务压过分类。**

`models/qc_hgt.py:309–327` 在整个 batch 的节点集合抽“错误连接”。按当前图结构与 B=128 计算，约 99.35%–99.41% 候选实际来自别的图；这个数是采样分布的理论期望，不是训练日志的经验计数。它与跨窗口负例高度重复，未充分训练同图关系辨别。另一分支直接选择 batch 下一图（299–306），没有核对 run 或时间距离。稳定窗口移位三步后，七统计量可能几乎不变，却被标为负例。

先做三项修改：同图同类型非邻接采样；显式按 run/时间间隔选跨图负例并剔除近重复；在原始时序表示上验证时移负例是否可辨。缺少有效负例时跳过，不能为了固定数量制造矛盾标签。不要把所有跨 run 同类工况强行解释为“物理不一致”。

分类目标先 warm-up，再逐渐加入辅助损失。验证候选可先用 lambda_c={0,0.02,0.05,0.1,0.2}，lambda_q={0,0.1,0.5} 的小型顺序搜索，而非一次笛卡尔穷举。记录 L_cls/L_q/L_c、梯度范数和分类与辅助梯度方向；只有确实存在梯度冲突再考虑 PCGrad 等额外技术。冻结/预训练质量分支也只是待验证备选。

**优先级 5：把现有算力用于独立样本和充分训练。**

当前 5,000 训练窗口按每 run 20 窗口抽取，实际覆盖约 252 条训练 run，而可用训练 run 为 8,400。先在相同 5,000 窗口预算下比较每 run 5 窗口（约 1,008 run）与原方案，避免将更多重叠窗口误当作更多独立数据。随后对所有参评模型共同提高到 25,000/50,000 窗口。

十次 QC 训练全部跑满 30 轮，最佳 epoch 位于 27–30；这是预算可能不足的证据，不是延长训练必然提分的证明。先固定样本比较 100–150 轮上限、patience 15–20、warm-up+cosine 或验证集学习率调度。以验证 Macro-F1 选 checkpoint，不用训练 loss 在不同辅助损失权重间直接判优。

源码中 `compute_auxiliary_loss=True` 固定传入（`models/qc_hgt.py:587`），推理及禁用该损失时仍生成负例；逐边 Python 采样还会拖慢 GPU。应只在训练且该辅助损失开启时构造负例，并向量化同图候选采样。它首先是效率修复，不能直接记为准确率提升。禁用评估随机负采样会改变 RNG 消耗，复现实验时需固定并分离训练、评估随机源。

检测到本机为 RTX 3050 Laptop GPU，4 GiB 显存。第一版按 hidden=64、2 图层、micro-batch=16/32 起步，以梯度累积保持有效 batch，并先测峰值显存和每 epoch 用时；候选窗口与数据缓存仍需控制。暂不建议一次部署大型基础模型、复杂 Mamba 和大规模网格。

还有一个容易使调参无效的工程问题：`scripts/run_protocol.py:202–207` 看到同名结果 `complete=true` 就跳过，232–236 可复用旧 checkpoint，没有验证配置/代码 hash。每个新实验必须使用独立输出目录并保存有效配置、代码版本、run/窗口索引和数据指纹；不能直接改 YAML 后在原 `results/stage5` 中 resume。

LSTM-GatedTAG 出版商摘要报告 Macro-F1 88.94%、Accuracy 88.21%。这说明相近任务存在高性能方法，不能由此推断本文可获得同样分数，也不能用该数值减去本文结果作为公平性能差距。应取得完整设置、代码或按方法复现后统一重跑。

[Graph-Mamba](https://arxiv.org/abs/2402.00789) 可作为探索备选；当前仅 58 节点、W=30，其大图长程效率优势不是首要需求。[2026 PHM 的时空 GATv2](https://papers.phmsociety.org/index.php/phme/article/view/4949) 使用正常数据训练做检测，不能把检测分数放进21类故障分类主表。详细来源、代码状态和其他候选见 [文献核查记录](qc_hgt_sota_references_20261104.md)。

**建议的最小实验路径。** 以下是可执行的研究计划，尚未实现或测得改进分数。

| 阶段 | 实验 | 固定因素与判定 |
| --- | --- | --- |
| A：确定主要信息瓶颈 | 原模型、仅固定标准化、仅ID、标准化+ID，4组 | 先P2、原5,000窗口/30轮、seed0筛选；只看验证集，随后用seed1/2确认排序 |
| B：增加时序表示 | A最佳版、+TCN、相同TCN和骨干但无q/c | 同run/窗口/退化预算；测分类提升是否来自时序或q/c |
| C：修复协同 | B最佳版上分别测试value gate、负采样、联合；补q-only/c-only/无q-c | 关注P2已见验证条件，未见测试组合不用于选超参 |
| D：确认预算 | 相同5,000窗口更多独立run；再增加训练轮数、训练样本 | 因素逐项比较，基线同步得到预算；每配置记录wall-time/显存 |
| E：正式对比 | CNN或TCN、Temporal-HGT、新QC、GNN-TAM、TEP-ASTGCN；资源允许加GraphGPS和一个2026方法 | 冻结方案后P1/P2、五种子；不同协议分别报告，不混用checkpoint |

为了控制成本，先完成 A/B，再决定是否进入 C/D，不需要一开始把全部候选跑满五种子。严格 P1 与 P2 的训练分布保持各自定义；增强预训练版本另列表。若更长窗口改善困难类，需要同时报告新增延迟与早期故障召回，不能只评估长时间稳定故障。

**性能证据与论文表达应同时升级。** 主表同时给 Accuracy、Macro-F1 的均值±样本标准差，另外保留每类召回、Normal误报、退化下降量、参数量和推理时间。不要删除 IDV3/9/15 或正常类来制造更高主表分数；如附加常见的困难类排除设置，必须清楚标成另一个任务。当前正常类训练/验证约4.8%，测试343/2000=17.15%，且训练与测试的故障发生时刻不同，应增加基于训练数据的正常/故障及发生后时间段采样分析，不能根据测试比例直接调先验。

现有 P1 Clean 的 QC-HGT-HGT 同种子差值均值为 +1.47 个 F1 百分点，五种子配对 t 区间约 [-2.93,+5.86]；P2 Unseen 为 +1.09，区间约 [-3.21,+5.39]。这是固定划分下训练随机性的粗略区间（n=5、分布假设较强），两者均含零，当前不能写“统计显著优于HGT”。正式结果还应按独立run做配对聚类bootstrap；不可把高度重叠窗口作为独立样本来夸大显著性。

第一阶段可以把“验证集稳健提高至少5个Macro-F1百分点”设为继续投入的工程门槛，这只是目标，不是效果预测。最终核心标准应是：在同输入、同预算的 Temporal-HGT、强时序基线及先进图基线上，多种子表现稳定，双模块的增益可由同骨干消融解释。将当前表示瓶颈修复、时序建模收益、质量/一致性收益分别证明，才能支撑更有说服力的论文贡献。
